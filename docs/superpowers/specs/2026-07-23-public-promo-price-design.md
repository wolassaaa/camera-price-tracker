# 公开促销价与响应式仪表盘设计

## 目标

在不使用账号 Cookie、联盟凭据、验证码绕过或结算流程自动化的前提下，显示可公开验证的促销后价格；同时让窄屏、缩放和长来源列表保持可读。

## 价格模型

每条报价保留标价和货币，并新增可选的促销组成：公开优惠券、满减、支付立减和促销后价。促销后价只有在商品页或公开活动数据明确给出优惠金额/门槛时才计算。记录证据 URL、有效期、可用性和可信度；缺失地区、会员或账号条件时标记为“需账号确认”，不作为最低可购价。

## 采集边界

- JD：使用公开 SKU 基础价，并解析公开可见的促销字段（若存在）。
- 淘宝/天猫：尝试公开详情数据和 JSON-LD；被拒绝、要求登录或验证码时记录来源状态并停止，不持久化 Cookie，也不重试绕过。
- 已有官方、Price.com 和手工导入来源继续作为独立市场分段。

## 历史数据

历史记录只来自公开可验证的价格序列、现有已采集数据库或用户导入 CSV。每个历史点保留来源和抓取时间；无法证实的“历史最低价”不写入数据库。公开页不存在历史序列时，从当前开始累积。

## 界面

采用信息密度可控的卡片网格：

- 顶部显示当前产品、可信参考价、公开促销后价和来源状态。
- 数据源改为可折叠、按平台分组的列表，避免商家级 Price.com 来源压垮页面。
- 图表、比较和设置表单在 900px 以下单列显示；标签与输入框自动换行，按钮占满可用行宽。
- 窄屏不使用绝对定位；所有栅格列使用 `minmax(0, …)` 并允许长文本截断或换行。

## 失败处理与验证

采集器将公开促销信息不足、登录墙与验证码区别记录。新增适配器、价格计算、历史导入、窄屏 CSS 和页面结构测试；通过容器运行一次采集、验证首页与 API，并检查 320px/768px/桌面宽度下无水平溢出或控件重叠。
