# 本地浏览器券后价自动巡检设计

## 目标

把“券后到手价”而非标价作为 JD 商品的有效监控价格。巡检应使用用户日常 Chrome 的已登录会话，不导出、读取、存储或传输 Cookie；遇到登录失效、验证码或页面异常时立即停止该商品的后续巡检并在本地面板显示原因。

## 选定方案

交付一个未发布、仅本机加载的 Chrome 扩展。扩展使用浏览器自身的后台标签页和页面内容脚本访问用户在仪表盘中登记的商品 URL。它仅向 `http://localhost:8000` 发送已解析的非敏感结果：平台、商品 ID、SKU URL、页面可见的价格、促销文本、配送地标签、采集时间和状态。会话 Cookie 始终只由 Chrome 发往对应电商域名，扩展不申请或使用 Cookie 权限。

## 数据流程

1. 用户在现有仪表盘登记精确 SKU 的 JD 商品 URL，并保持正常 Chrome 已登录、配送地为大陆地址、JD 域名走稳定直连网络。
2. 扩展按每个商品至少 60 分钟一次的间隔，在后台打开或刷新一个非激活标签页。
3. JD 内容脚本从可见 DOM 中提取当前 SKU、价格、优惠说明和明确标记为“预计到手价”或等价文案的金额。
4. 若页面明确展示券后价，扩展将该值连同促销证据提交给本地 API，系统将它记录为 `account_visible` 价格；若只出现标价，则记录为“券后价不可得”，而不是把标价作为推荐价。
5. 若页面包含登录墙、验证码、账号异常或配送地不在大陆的信号，扩展不重试、不点击、不切换账号，写入受控失败状态并暂停该商品，等待用户自行恢复浏览器会话。

## 边界

- 首版只支持 JD 商品页上直接可见的券后价；不自动领券、加购、进入结算页、提交订单或付款。
- 不依赖开发者注册、联盟 PID、第三方价格服务或 Cookie 导出。
- 未显示到手价时结果为未知；不会推断、拼凑或虚构券后价。
- 后台标签页可被 JD 拒绝，系统将停止而不是通过 VPN、设备伪装、验证码绕过或高频重试来规避限制。

## 组件

- `extension/manifest.json`：Manifest V3、最小 `tabs`/`scripting`/`alarms` 权限和 JD 域名匹配。
- `extension/service-worker.js`：读取本地已登记 URL、按低频调度后台标签页、接收内容脚本结果并 POST 到 localhost。
- `extension/content/jd.js`：纯 DOM 提取器，不读取 Cookie、不调用购物车/结算动作。
- 本地 API：新增受限的浏览器报价接收端点，验证来源字段、金额、时间与 URL，并存入现有 SQLite 历史。
- 仪表盘：新增“账户可见券后价”卡片，显示证据、采集时间、可用性和暂停原因。

## 验证

- 单元测试：JD 页面样本中可提取到手价、优惠文本和异常页面信号；无到手价不会生成可购买价格。
- API 测试：只接受 localhost 扩展提交的字段，不接受 Cookie 字段或结算/订单字段。
- 手动验收：在正常 Chrome 中加载扩展并登录 JD，登记一个精确 SKU URL；扩展写入页面可见券后价或明确的不可得状态；验证码/异常页面不会触发第二次操作。

## 后续

PDD 和淘宝作为独立内容脚本后续加入，保持同一安全与停止策略。购物车结算价需要单独设计并取得用户对“自动加购”的明确授权，不属于首版。
